# こけにわ

毎日のタスクを重要度（高・中・低）で分けて、達成度を植物の育ち方で見るタスク管理アプリです。
iPhone と Windows の両方で同じデータを使えて、iPhone のホーム画面・ロック画面にウィジェットを置けます。

```
 iPhone（ホーム画面に追加したWebアプリ） ─┐
 Windows（Edgeでインストールしたアプリ） ─┼─ GitHub Pages（アプリ本体） ─ Supabase（データ）
 iPhoneのウィジェット（Scriptable） ──────┘                         └ 読み取り専用キーで参照
```

## 費用

0円で動きます。ただし、次の条件があります。

| 使うもの | 役割 | 無料で使う条件 |
|---|---|---|
| GitHub Pages | アプリの公開 | リポジトリを **公開（Public）** にする |
| Supabase | データの保存とログイン | 無料プランはアクティブなプロジェクト **2つまで**。**1週間使わないと一時停止**（管理画面から再開できる） |
| Scriptable | iPhoneのウィジェット | 無料アプリ |

---

## セットアップ手順

所要時間の目安は30〜40分です。Supabase と GitHub の画面の名前は、変わることがあります。見つからないときは近い名前の項目を探してください。

### 1. Supabase のプロジェクトを作る

1. https://supabase.com にログインし、「New project」を押す
2. 次のように入力して作成する
   - Name：`kokeniwa`
   - Database Password：長いパスワードを自動生成して、パスワード管理アプリに保存
   - Region：Northeast Asia (Tokyo)
   - Plan：Free
3. 作成が終わるまで1〜2分待つ

> 無料プロジェクトが既に2つある場合は、ここで作れません。別アプリのプロジェクトに相乗りすると、データとアクセス権の管理が混ざるのでおすすめしません。

### 2. テーブルを作る

1. 左のメニューから「SQL Editor」を開き、新しいクエリを作る
2. このリポジトリの `supabase/schema.sql` を全部コピーして貼り付け、「Run」を押す
3. 「Success」と出ればOK。「Table Editor」に `app_state` と `widget_tokens` ができていて、どちらも RLS が有効になっていることを確認する

`schema.sql` は何度実行しても壊れないように書いてあります。

### 3. 自分のユーザーを作る

アプリには新規登録の画面がありません。ユーザーは管理画面で作ります。

1. 「Authentication」→「Users」→「Add user」→「Create new user」
2. メールアドレスとパスワードを入れ、**「Auto Confirm User」をオン** にして作成する
3. **新規登録を止める**：「Authentication」の設定（「Sign In / Providers」など）で「Allow new users to sign up」をオフにする
   - これで、URLを知った他人がアカウントを作ることはできなくなります

### 4. 接続設定を書く

1. Supabase のプロジェクト画面上部の「Connect」を押し、次の2つを確認する
   - **Project URL**（`https://〜.supabase.co`）
   - **Publishable key**（`sb_publishable_〜`）
2. `config.js` を開き、2つの値を書き換える

```js
window.KOKENIWA_CONFIG = {
  SUPABASE_URL: 'https://abcdefghijklmnop.supabase.co',
  SUPABASE_KEY: 'sb_publishable_xxxxxxxxxxxxxxxx'
};
```

> **secret key（`sb_secret_〜`）や service_role key は絶対に書かないでください。**
> `config.js` はGitHubで公開されます。秘密キーが漏れると、RLSを無視してデータベースを操作できてしまいます。
> うっかりコミットした場合は、ファイルを消すだけでは足りません（履歴に残ります）。すぐに Supabase の「Settings」→「API Keys」でそのキーを無効化して作り直してください。
> なお、アプリは起動時に秘密キーが入っていないか確認し、入っていたら動かずに警告を出します。

### 5. GitHub Pages で公開する

1. GitHub で新しいリポジトリ `kokeniwa` を **Public** で作る（README などは追加しない）
2. VS Code でこのフォルダを開き、ターミナルで次を実行する（`<ユーザー名>` は自分のもの）

```bash
git init
git add .
git grep -n "sb_secret_[A-Za-z0-9]"   # 何も表示されなければOK（秘密キーが入っていない）
git commit -m "こけにわ 初版"
git branch -M main
git remote add origin https://github.com/<ユーザー名>/kokeniwa.git
git push -u origin main
```

3. GitHub のリポジトリで「Settings」→「Pages」を開き、Source を「Deploy from a branch」、Branch を `main` / `/(root)` にして「Save」
4. 数分待つと `https://<ユーザー名>.github.io/kokeniwa/` で開けるようになる

### 6. iPhone と Windows に入れる

**iPhone**
1. Safari で `https://<ユーザー名>.github.io/kokeniwa/` を開く
2. 共有ボタン →「ホーム画面に追加」
3. ホーム画面のアイコンから開いてログインする（Safari とホーム画面のアプリは、ログイン状態が別々です）

**Windows**
1. Edge で同じURLを開く
2. 右上の「…」→「アプリ」→「このサイトをアプリとしてインストール」
3. スタートメニューやタスクバーから起動できるようになる

### 7. iPhone のウィジェットを置く（Scriptable）

1. App Store で「Scriptable」を入れる
2. `widget/kokeniwa-widget.js` の先頭にある3つの値を書き換えて、GitHub に push する
   - `APP_URL`：手順5のURL
   - `SUPABASE_URL` / `SUPABASE_KEY`：手順4と同じ値（公開用キーなので公開しても問題ありません）
3. iPhone の Safari で GitHub の `widget/kokeniwa-widget.js` を開き、「Raw」を押して全文をコピーする
4. Scriptable で「＋」→ 貼り付け → 画面上部のタイトルを「こけにわ」に変更
5. こけにわアプリの「ウィジェット」タブで **「キーを発行」** を押し、表示されたキーをコピーする
6. Scriptable で ▶ を押して実行し、キーを貼り付ける。プレビューが出ればOK
7. ホーム画面を長押し →「＋」→「Scriptable」→ 小か中を追加 → ウィジェットを長押し →「ウィジェットを編集」→ Script に「こけにわ」を選ぶ
8. ロック画面に置くときは、ロック画面を長押し →「カスタマイズ」→ ウィジェットの枠から Scriptable を追加し、同じように「こけにわ」を選ぶ

- ウィジェットをタップすると、Safari でアプリが開きます
- 更新はiOSが決めたタイミング（目安15分ごと以上）なので、チェックしてすぐには反映されません
- 通信できないときは、前回取得した内容に「前回 HH:MM の情報」と付けて表示します

### 8. アプリを更新するとき

ファイルを編集して `git push` すれば、数分で GitHub Pages に反映されます。アプリは開くたびにネットから最新版を読み込みます（オフラインのときだけ、端末に保存した版を使います）。

## セキュリティの設計

| 守りたいもの | 対策 |
|---|---|
| 他人のデータを読む・書く | RLS で、ログイン中のユーザーは自分の行しか読めず、書けない。未ログイン（anon）にはテーブルの権限を一切与えていない |
| 他人がアカウントを作る | 管理画面でユーザーを作り、新規登録はオフにする |
| ウィジェットのキーが漏れる | キーは256ビットの乱数。DBにはSHA-256のハッシュだけを保存。キーでできるのは読み取りだけで、アプリからいつでも取り消せる。最終利用日時も見える |
| 秘密キーを公開してしまう | アプリとウィジェットの両方が、秘密キーを検出したら動作を止めて警告する |
| 画面への不正なスクリプト注入 | タスク名は表示前にエスケープ。さらに CSP で、自分のサイト以外のスクリプトを読み込めないようにしている |
| 共用PCにデータが残る | ログアウト時に、その端末のキャッシュを消す |
| DBの肥大化 | 1ユーザーの保存データは最大1MBまで |

`schema.sql` は、Supabase と同じ権限構成を再現したローカルの PostgreSQL で、次の19項目を確認済みです。

- 自分の行は作れるが、他人の `user_id` では作れない（タスク・キーとも）
- 他人の行は「見えない」「更新できない」「削除できない」
- 未ログインではどちらのテーブルも読めない（権限エラー）
- 正しいキーでだけ状態が返り、間違ったキー・短すぎるキー・SQL的な文字列ではすべて空が返る
- キーの最終利用日時が記録される
- 1MBを超えるデータは保存できない

**残るリスク**：タスクの内容は、Supabase上で平文のまま保存されます（ディスクの暗号化はSupabase側で行われます）。パスワードなどの秘密はタスクに書かないでください。

## 制約

- 同期は「後から保存した方が勝つ」方式です。2台で同時にオフラインのまま編集すると、片方の変更が消えることがあります
- 1週間アプリを使わないと、Supabase の無料プロジェクトが一時停止します。止まったら管理画面から再開してください
- 七十二候の日付は目安で、年によって1日前後します
- claude.ai で公開していたデモ版のデータは、引き継がれません

## ファイル構成

```
index.html            画面（ログイン・今日・記録・ウィジェット）
style.css             見た目
app.js                動き（タスク管理・集計・同期・ログイン・ウィジェット用キー）
config.js             接続設定（公開用の値だけ）
sw.js / register-sw.js  オフライン対応
manifest.webmanifest  ホーム画面に追加したときの名前・アイコン
icons/                アイコン
vendor/supabase.js    Supabase のライブラリ（@supabase/supabase-js 2.117.2, MIT）
supabase/schema.sql   テーブル・アクセス制御・ウィジェット用の読み取り口
widget/kokeniwa-widget.js  Scriptable 用ウィジェット
```

## デモ版からの変更点

デモ版の機能は、すべてそのまま残しています。
重要度（高・中・低）ごとの一覧、育つ植物と達成率、週のリング表示、「毎日」と「この日だけ」のタスク、前日の繰り越し、元に戻す、サンプルデータ、七十二候、記録タブ（苔の記録・重要度ごとの達成率・連続達成）、ウィジェットのプレビュー、ダークモードが含まれます。

変更・追加したのは次の点です。
- 保存先を claude.ai から Supabase に変更（端末内にもキャッシュし、オフラインでも使える）
- ログイン・ログアウトを追加
- ウィジェット用キーの発行・一覧・取り消しを追加
- ホーム画面に追加・インストールできるように（manifest、Service Worker、アイコン）
- 設定ミス（未設定・秘密キー）の検出と、CSP を追加
